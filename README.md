# Codex Pool для Hermes Agent

Несколько подписок ChatGPT (Plus/Pro/любые) → **один локальный шлюз** → Hermes,
Codex CLI и Claude Code работают через него, не замечая, что аккаунтов
несколько. Шлюз сам ротирует аккаунты, «охлаждает» упёршиеся в лимит,
ретраит 429/5xx. Ручное переключение аккаунтов больше не нужно нигде.

```
Hermes / Codex CLI / Claude Code  →  CLIProxyAPI :8317  →  chatgpt.com (аккаунт 1..N)
                                                        →  claude.ai   (опционально, Claude Pro/Max)
```

Шлюз — [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) (Go,
open source). Этот репозиторий — готовая **обвязка**: конфиг, сервисы, сторож,
утренний отчёт по квотам, бэкап токенов и самоустанавливающийся скилл для
Hermes-агента, который делает всё сам.

> ⚠️ **Честное предупреждение.** Использование подписочного OAuth ChatGPT/Claude
> вне официальных клиентов может нарушать ToS OpenAI/Anthropic — риск ограничения
> аккаунта ненулевой. Шлюз маскируется под официальный Codex CLI, но гарантий нет.
> Лимиты подписки общие с вашим «ручным» Codex CLI. Решение — за вами.

## Как поставить у себя (10 минут + логин в каждый аккаунт)

Репозиторий — самоустанавливающийся скилл: ваш Hermes-агент сам всё сделает.

**Шаг 1.** Скажите своему Hermes-агенту:

```
Установи скилл и настрой мне пул Codex-аккаунтов по нему:
https://raw.githubusercontent.com/artemiimillier/hermes-codex-pool/main/SKILL.md
```

(либо `hermes skills install <та же ссылка>` и попросите агента выполнить скилл,
либо клонируйте репо и скажите: «прочитай SKILL.md и выполни»).

**Шаг 2.** Агент соберёт шлюз из исходников, поставит конфиг и сервис, а вам
покажет ссылку вида `https://auth.openai.com/oauth/device?user_code=XXXX-XXXX`
— откройте, войдите в **первый** аккаунт ChatGPT, подтвердите код. Повторите
для каждого аккаунта (в браузере — режим инкогнито или выход из аккаунта между
логинами).

**Шаг 3.** Агент проверит цепочку: `healthz` → список моделей → настоящий
запрос → и подключит Hermes (провайдер `codexpool`, алиасы `pool-*`).

Требования: Linux (s6-overlay контейнер или systemd), Python 3, Go (агент
скачает сам), 2+ подписки ChatGPT. macOS — должно работать с launchd, но
не проверялось.

## Что внутри

| Путь | Назначение |
|---|---|
| `SKILL.md` | Инструкция для Hermes-агента: сборка, логин, сервис, провайдер, кроны, проверка, подводные камни |
| `config.yaml.template` | Конфиг шлюза: loopback-only, панель выключена, round-robin + session-affinity, короткий список моделей |
| `scripts/codex_pool_report.py` | Отчёт по квотам всех аккаунтов (Codex + Claude) для Telegram; `--alerts` — только проблемы |
| `scripts/codex_pool_alerts.sh` | Обёртка для крона (поле script не принимает аргументы) |
| `scripts/codex_pool_backup.sh` | Ежедневный tar.gz токенов, ротация 14 копий |
| `scripts/cliproxy-watchdog.sh` | Сторож: реанимирует шлюз, молчит когда всё живо |
| `scripts/cliproxy_update_check.py` | Раз в неделю сообщает о новом релизе шлюза (обновление — только вручную, после аудита diff) |
| `scripts/claude-pool.sh` | Запуск Claude Code поверх пула (модели GPT через Anthropic-совместимый эндпоинт) |
| `scripts/s6/cliproxy/run` | Сервис для s6-overlay (rootless контейнеры) |
| `scripts/systemd/cliproxy.service` | user-юнит для обычного Linux |

## Что получаете после установки

- В Hermes: `/model pool-astra` (и любые другие алиасы) — запросы уходят на
  свободный аккаунт; один разговор держится на одном аккаунте (кэш промптов).
- Кроны Hermes закрепляются на `codexpool` и не встают, когда один аккаунт
  упёрся в недельный лимит.
- Codex CLI работает через тот же шлюз (`model_provider = "pool"`).
- Claude Code можно запускать на моделях GPT через пул (`claude-pool`).
- Утром в Telegram: процент израсходованного окна по каждому аккаунту, дата
  ресета, число доступных ручных сбросов. Днём — тишина, если всё хорошо.
- Опционально в тот же пул добавляются аккаунты Claude Pro/Max — тогда
  появляется провайдер `claudepool` и алиасы `pool-sonnet` / `pool-opus`.

## Почему сборка из исходников, а не релизный бинарь

Шлюз — сторонний проект, который держит в руках OAuth-токены ваших аккаунтов.
В скилле: клон по пинованному тегу, `grep` diff на новые домены, сборка
`go build -trimpath`, `disable-control-panel: true` (без отзвона на сайт
авторов), `host: 127.0.0.1` (наружу не светится). Обновления — только руками,
после того же аудита.
