# Шлюз подписки Claude (и ChatGPT, Kimi) для Hermes Agent

**Что это.** Шлюз, через который Hermes работает по вашей обычной подписке
**Claude Pro/Max** — без платного API-ключа. В тот же шлюз можно добавить
подписки **ChatGPT Plus/Pro** и **Kimi**, и сколько угодно аккаунтов каждой:
шлюз сам переключает запросы на свободный аккаунт, а упёршийся в лимит
отправляет «отдыхать» до сброса. По утрам — отчёт в Telegram: сколько лимита
осталось на каждом аккаунте. Хватает и одного аккаунта Claude.

**Как поставить — одной фразой своему Hermes-агенту:**

```
Установи и настрой мне шлюз подписок по этой инструкции:
https://raw.githubusercontent.com/artemiimillier/hermes-codex-pool/main/SKILL.md
```

Агент соберёт шлюз, запустит его и попросит вас войти в аккаунт: для Claude
он пришлёт ссылку, вы входите, нажимаете Authorize и отправляете агенту адрес
из браузера (пошагово — в [SKILL.md, раздел «Claude Pro/Max»](SKILL.md#claude-promax)).
Потом агент подключит шлюз к Hermes, и в выборе моделей появятся модели Claude.

**Хотите видеть остаток лимитов прямо в Hermes Desktop** — поставьте плагин
[hermes-codex-limits](https://github.com/artemiimillier/hermes-codex-limits)
(после пула).

> ⚠️ **Честно о риске.** Подписка Claude/ChatGPT рассчитана на официальные
> приложения. Использование её через сторонний шлюз может нарушать правила
> Anthropic/OpenAI, и аккаунт могут ограничить. Лимиты общие с вашим обычным
> использованием подписки. Решение — за вами.

```
Hermes / Codex CLI / Claude Code  →  шлюз CLIProxyAPI :8317  →  claude.ai    (аккаунты Claude Pro/Max)
                                                             →  chatgpt.com  (аккаунты ChatGPT)
                                                             →  api.kimi.com (подписка Kimi, по ключу)
```

Шлюз — [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) (Go,
open source). Этот репозиторий — готовая **обвязка** к нему: конфиг, сервис,
сторож, утренний отчёт по лимитам, бэкап токенов и инструкция (SKILL.md),
по которой Hermes-агент ставит всё сам. Название репозитория историческое —
начиналось с пула аккаунтов Codex.

## Что нужно

- Сервер или компьютер с Linux, на котором уже работает Hermes Agent
  (s6-контейнер, systemd или просто фоновый процесс). macOS не проверялась.
- Python 3, git, curl. Go агент скачает сам (в домашнюю папку, root не нужен).
- Минимум одна подписка: Claude Pro/Max, ChatGPT Plus/Pro или Kimi.
- Время: ~10 минут на сборку и настройку + 1–2 минуты на вход в каждый аккаунт.

## Как проходит установка

1. **Сборка.** Агент собирает шлюз одобренной версии из исходников (3–10 минут), кладёт конфиг,
   запускает сервис и проверяет, что шлюз отвечает.
2. **Вход в аккаунты**, по одному:
   - **Claude** — агент присылает ссылку `claude.ai/oauth/authorize…`; вы входите,
     жмёте Authorize; браузер покажет ошибку на `localhost:54545` — это нормально;
     копируете весь адрес из адресной строки и отправляете агенту. На всё
     ~3 минуты, иначе ссылку придётся запросить заново.
   - **ChatGPT** — агент присылает ссылку `auth.openai.com/codex/device` и код;
     вы входите и вводите код (код живёт 15 минут).
   - Второй и следующие аккаунты — так же, в режиме инкогнито или выйдя из
     предыдущего аккаунта в браузере.
3. **Подключение к Hermes.** Агент добавляет провайдера `pool` (адрес шлюза
   `http://127.0.0.1:8317/v1`), делает его основным и проверяет настоящий запрос.
   В Hermes выбирайте модель через `/model` или в списке моделей.

Другие способы: `hermes skills install <ссылка на SKILL.md выше>` и попросить
агента выполнить скилл, либо клонировать репозиторий и сказать агенту
«прочитай SKILL.md и выполни».

## Что внутри

| Путь | Назначение |
|---|---|
| `SKILL.md` | Инструкция для Hermes-агента: сборка, логин, сервис, провайдер, кроны, проверка, подводные камни |
| `config.yaml.template` | Конфиг шлюза: только loopback, панель и плагины шлюза выключены, round-robin + session-affinity, короткий список моделей |
| `scripts/codex_pool_report.py` | Отчёт по квотам всех аккаунтов (Codex + Claude) для Telegram; `--alerts` — только проблемы |
| `scripts/codex_pool_alerts.sh` | Обёртка для крона (поле script не принимает аргументы) |
| `scripts/codex_pool_backup.sh` | Ежедневный tar.gz токенов, хранятся 3 последние копии |
| `scripts/cliproxy-watchdog.sh` | Сторож (каждые 2 минуты): поднимает шлюз после падения или перезапуска контейнера, молчит, когда всё живо |
| `scripts/cliproxy_update_check.py` | Раз в неделю сообщает, если здесь одобрена новая версия шлюза; обновление — фразой агенту «обнови пул» |
| `scripts/cliproxy-approved.txt` | Одобренная версия CLIProxyAPI: тег и точный коммит. Установка и обновления собирают только её |
| `scripts/cliproxy-known-hosts.txt` | Эталон сетевых адресов одобренной версии, разложенный по назначению |
| `scripts/cliproxy_audit_hosts.sh` | Аудит исходника перед сборкой: показывает только адреса, которых нет в эталоне |
| `scripts/install_go.sh` | Ставит Go в `~/go` с проверкой SHA-256 по go.dev (если Go ещё нет) |
| `scripts/claude-pool.sh` | Запуск Claude Code поверх пула (любые модели пула, включая GPT) |
| `scripts/s6/cliproxy/run` | Сервис для s6-overlay (rootless контейнеры) |
| `scripts/systemd/cliproxy.service` | user-юнит для обычного Linux |

## Что получаете после установки

- В Hermes: модели Claude/GPT/Kimi из вашего пула в обычном списке моделей и
  по коротким именам (`/model pool-sonnet` и т.п.) — запросы уходят на
  свободный аккаунт; один разговор держится на одном аккаунте (кэш промптов).
- Кроны Hermes закрепляются на `pool` и не встают, когда один аккаунт
  упёрся в недельный лимит.
- Codex CLI работает через тот же шлюз (`model_provider = "pool"`).
- Claude Code можно запускать через пул, в том числе на моделях GPT (`claude-pool`).
- Утром в Telegram: процент израсходованного окна по каждому аккаунту, дата
  ресета, число доступных ручных сбросов. Днём — тишина, если всё хорошо.
- Аккаунты Claude и ChatGPT живут в одном провайдере `pool`: отдельный
  провайдер под каждую подписку не нужен.
- Подписки, которые дают не OAuth, а API-ключ (например Kimi), тоже кладутся
  в этот же пул — блоком `claude-api-key` в конфиге шлюза. Смысл в том, чтобы
  ВСЕ подписки жили в одном месте, а не россыпью по разным провайдерам.

## Безопасность: как собирается и куда ходит шлюз

Шлюз — сторонний проект, который держит OAuth-токены ваших аккаунтов, поэтому:

- **Своя сборка одобренной версии.** Скилл клонирует исходник CLIProxyAPI по тегу
  из `scripts/cliproxy-approved.txt` и сверяет точный коммит: если тег у авторов
  перевесят на другой код, сборка остановится.
- **Аудит сети.** Перед сборкой `cliproxy_audit_hosts.sh` сравнивает адреса в
  исходнике с эталоном и показывает только новые — агент показывает их вам до сборки.
- **Ничего наружу.** Шлюз слушает только `127.0.0.1`; удалённое управление, веб-панель
  и плагины шлюза выключены.

Куда шлюз ходит сам при такой настройке:

- серверы Anthropic и OpenAI (и Kimi, если добавили) — это и есть работа с вашими аккаунтами;
- раз в 6 часов — сервер с номером версии клиента Antigravity (встроено в шлюз,
  не отключается; токены туда не уходят).

Каталоги моделей с серверов авторов (раз в 3 часа) выключены флагом `--local-model`:
список моделей берётся из собранной версии и обновляется вместе с ней.

## Как вести одобренную версию (для того, кто раздаёт скилл)

Ученики и друзья обновляются только на версию, которую одобрили вы:

1. На своём сервере включите уведомления о каждом релизе авторов: у крона
   `cliproxy-update-check` задайте `CLIPROXY_UPDATE_CHANNEL=upstream`.
2. Вышло что-то нужное — соберите новую версию у себя по разделу «Обновление»
   в `SKILL.md`, прогоните `cliproxy_audit_hosts.sh`, проверьте живыми запросами.
3. Обновите `scripts/cliproxy-approved.txt` (тег + коммит) и, если аудит показал
   новые адреса, `scripts/cliproxy-known-hosts.txt` (`cliproxy_audit_hosts.sh --list <src>`).
4. Опубликуйте. В течение недели у всех придёт «одобрена новая версия шлюза».
